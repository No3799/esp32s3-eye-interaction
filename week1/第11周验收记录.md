## 一、三层为什么必须分开

```
原始观测   IMU 合加速度 0.932 g ／ 影像 3 天前的快照 ／ 视觉模型判 blocked 0.90
   ↓ 有限规则 + 有效时间窗
派生状态   motion=基本静止（R1）／ camera_view=模型判断已过期（R3）／ location=没有可用位置（R4）
   ↓ 判断这句话能不能答、要不要问
交互决策   答「没有定位数据源，不能给出坐标」＋ 追问「要按设备/房间来问吗」
```

**跳过中间层的后果**，用本周真实碰到的一次错误说明：

> 视觉记录里有一条三天前的 `blocked @ 0.90`。第一版派生层直接取"最新一条视觉结果"，
> 于是待确认里冒出一句「**现在**画面被挡住了」。图确实是那张图、判断确实是那个判断，
> 但它是三天前的 —— 拿它说"现在"，就是拿旧结论冒充新事实。

修法不是删掉这条判断，而是给它加有效窗：超过 300 秒就只允许说「模型判断已过期（119.4 小时前）」，
并且不再进待确认。**数据没坏，是它过期了** —— 这两件事在界面上必须分开。

## 二、冲突样例记录（自动检出，非写死）

| 样例 | 页面/接口里的原文 | 为什么算冲突 | 系统怎么处理 |
|---|---|---|---|

**A. 规则层（进程内，用桩件构造现场不好复现的输入）**

```
✓ 遮挡没有被解释成危险
✓ 意图路由到 safety
✓ 把「遮挡」放进待确认，并追问现场情况
✓ 视觉判断标为「模型推断」，不混进观测事实
✓ 有人按求助时，待确认里出现「求助未回应」（唯一可信的人为证据）
✓ 求助项被标为 blocking（其它项不是）
✓ 10 分钟前的坐标判为「已过期」
✓ 过期坐标的说明里明确不能当当前状态
✓ 问位置时仍明确说不能给出坐标

✓ 三层结构齐全（observations / derived / decision）
✓ 每条派生都带规则编号与失效时间　—　缺失 0 条
```

## 五、没做到的和为什么

- **没有教师的"规则级事件关联骨架与对照数据"**。R1–R6 是自己定的，阈值（0.15 g、8 秒、300 秒）
  也是按本机噪声水平拍的，没有对照数据校准。
- **模型课的口径没对齐**。本项目把视觉输出标成 `inference` 并带自报分数，
  但"模型课怎么解释单项模型输出"没有统一格式，两边说法可能不一致。
- **端侧课的事件字段没对接**，仍是本项目自定义。
- **回答是规则拼的，不是自然语言生成**。这一周刻意不调模型：要证明的是"判断可追溯"，
  一旦让模型润色，就得再证明"润色没改事实"，那是另一周的活。
- **"危险"只能靠人按求助键**，这个口径本身也是一种取舍：如果哪天接入烟感、门磁这类硬件，
  R5 需要改，改成"哪些来源可以作为危险证据"，而不是"永远不能"。
