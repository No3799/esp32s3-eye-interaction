# 第 8 周 · 把视觉推理结果变成可理解反馈

> 课程：《AI交互原型与用户体验设计》（V2.1 修订建议稿）
> 周期：2026-11-02
> 硬件：ESP32-S3-EYE（OV2640）
> 模型：本地 Ollama `qwen2.5vl:3b`（3.8B / Q4_K_M / digest `fb90415cde1e`）

## 〇、任务卡原文与逐条对照

> **第8周　把视觉推理结果变成可理解反馈 | 理论1＋实践3学时**
>
> **本周问题**　模型返回一个标签和分数，系统应该如何表达"看到了什么"和"还有什么不能确定"？
>
> **前2学时**　讲解预测标签、分数、拒识及模型版本；本轮以画面可用性/遮挡识别为共同保底任务，场景粗分类作为拓展；接入真实模型推理。（理论1、实践1）
>
> **后2学时**　实现结构化结果解析、低分/未知反馈、重新采集和人工纠正；保留输入、结果和反馈三者对应，比较高分误判与正常样例。（理论0、实践2）
>
> **当堂验证**　未经校准的模型分数不写成现实正确率；场景类别不转换为精确位置或人身安全判断。

## 一、怎么做的

视觉模型不进服务器进程：`vision_agent.py` 只用标准库，通过 HTTP 调本机 Ollama。
好处是服务器仍然零第三方依赖，模型可以独立换（`NL_VISION_MODEL` 环境变量）。

一条链路的四段都有落点：

```
① 取图（第7周）       POST /api/snapshot        → 快照入库，有 id
② 推理（本周）         POST /api/vision          → 标签 + 自报分数 + 模型版本
③ 反馈（本周）         POST /api/vision/<id>/feedback → correct / wrong / skipped
④ 查看                 GET  /api/vision/list     → 结果与反馈合并，统计含"被纠正的"
```

第 ③ 步刻意**不覆盖**第 ② 步：反馈单独追加一条，读取时合并。
如果把 `corrected_label` 直接写回原记录，就再也看不到"模型原来怎么说的"——
而"模型错在哪"恰恰是这一周要比较的东西。

## 二、实测：四类样例 + 一个高分误判

模型首次加载 19.7 秒，之后每张 0.3~0.7 秒（常驻显存）。

| 样例 | 来源 | 规则判定 | 模型判定 | 自报分数 | 谁对 |
|---|---|---|---|---|---|
| SNAP-20261030-093445-0ac2 | **真实**（板子拍，失焦） | ok | **blocked** | 0.90 | ❌ 模型错，应是 `unclear` |
| _test_blocked | 合成（整块深色盖住） | ok | blocked | 0.90 | ✅ |
| _test_blurry | 合成（强高斯模糊） | ok | blocked | 0.90 | ✅ |
| _test_clear | 合成（红蓝黑三块几何图） | ok | **usable** | 0.90 | ✅ |

### 这张就是任务卡说的「高分误判」

第一张是板子 10-30 拍的真实画面：桌面、一块白色区域、几块深色，**整体失焦**。
模型说"画面被大面积遮挡"，自报 **0.90**。

实际上没有任何东西挡着 —— 只是糊。它把"糊"和"挡"混成一类了。
人工纠错改成 `unclear`（有画面但看不清是什么），**原判 blocked @ 0.90 仍留在记录里**。

### 更要紧的发现：四张样例，自报分数全是 0.90

| 判断 | 分数 |
|---|---|
| blocked（真被挡） | 0.90 |
| blocked（其实只是糊） | 0.90 |
| blocked（强模糊） | 0.90 |
| usable（清晰几何图） | 0.90 |

**分数完全没有区分度。** 模型对"我看清了"和"我看岔了"给的是同一个数。
这就是任务卡强调"未经校准的模型分数不写成现实正确率"的实证：
拿 0.90 当 90% 正确率，等于把四件事都说成一样可靠。

所以页面上的措辞固定是「模型自报 0.90（未校准）」，不给任何"准确率"暗示。

### 规则判定和模型判定经常不一致

四张样例里，快照层的规则判定（亮度/方差）**全部说 ok**，而模型三张说 blocked。
两个判据都不是真理：

- 规则只看亮度和方差 —— 一张"均匀的糊"在规则眼里完全正常
- 模型看的是语义 —— 但它会把"糊"误认成"挡"

接口里 `agree_with_rule` 字段把两个结论并排返回，**不一致时两条都留着**，
不挑一个当答案。界面上直接写："规则说 ok，模型说 blocked，两个都留着，谁对由人来定。"

## 三、界面

「影像」分区，快照下面多一块「模型怎么看这张图」：

- **看到什么**：一句话（"看到：画面被挡住了（桌面和键盘）"）
- **有多确定**："模型自报 0.90（未校准）· 本机往返 412 ms"
- **还不确定什么**：低分/拒识时给建议（"把镜头前的遮挡物移开，再拍一张"）
- **纠错**：判对了 / 判错了（选三档之一）/ 先不管
- **拒识**：模型没判出来时状态标"没判出来"，不是"识别成功"

## 四、坑

1. **模型没到位时要 503，不要落一条"拒识"记录**。一开始没区分，模型不可用也写了一条
   `rejected` 记录进库，把"系统故障"和"模型判不出来"混进同一个统计里。
2. **不要拿"三张都返回一样"当 bug**。第一反应是"图片没传进去"，
   做了对照实验（纯红图 → "红色"）才发现图片是传进去的，那三张确实都看不清。
   **先证伪自己的怀疑，再改代码。**
3. **首次推理 19.7 秒不是性能问题**，是模型加载进显存。第二次起 0.3~0.7 秒。
   把首帧耗时当常态会得出错误结论。

## 五、这一周的一句话结论

**能说清"看到什么"和"有多不确定"，并且绝不把模型的自评分当成正确率。**

具体说：四类样例都跑通、一次高分误判被抓出来并纠正、两条判据不一致时并排保留；
缺的是教师基线与失败样本（用开源模型和自建样例替代，已如实标注）。
