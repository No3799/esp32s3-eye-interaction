# 第1周 · 传感采集与 Web 展示系统

**日期**：2026-09-08 ~ 09-13
**设备**：ESP32-S3-EYE（板载 **QMA6100P** 三轴加速度计，I2C 0x12，SDA=GPIO4 / SCL=GPIO5）
**设备标识**：`device_id = team01-esp32s3eye`
**链路**：板子 WiFi（`10.1.41.160`）→ HTTP POST 1Hz → 本机服务器 `10.1.41.18:8000` → SQLite → 网页

---

## 一、这一周要证明什么

任务卡原话是：采集一个**真实**传感源 → **独立联网**上传 → 最小接收/存储/查询/Web 展示 → 当堂验证"停采后提示未更新"。

拆开就是四件事，每一件都要有能查的证据，不能只说"做好了"：

| 要证明的事 | 证据在哪 |
| --- | --- |
| ① 采的是真传感器的数，不是编的 | 数据库里 5000+ 条带 `src_ip=10.1.41.160` 的记录，静置合加速度 ≈ 1.00g |
| ② 板子自己联网上传，不是 USB 桥接 | 上报走 WiFi，`src_ip` 是板子 IP；USB 只用来烧录和看日志 |
| ③ 服务器能收、能存、能查 | `readings` 表 + `/api/latest`、`/api/history` |
| ④ 停采后页面要显示"未更新"，不能拿旧数字冒充新的 | 拔电后页面顶部转红并显示"已 N 秒"（见第四节） |

数据库 `week1/data/readings.db`，**截至第 1 周结束时** `readings` 表共 **5986** 条，其中真机（`src_ip=10.1.41.160`）**5435** 条。

## 四、"未更新"怎么验的

这是当堂验收点，也是最容易被糊弄过去的一条 —— 页面只要一直显示旧数字，看起来永远"正常"。

做法：拔掉板子电源，看页面顶部。实测结果是状态条转红、显示"已 N 秒"，并且**最后一次的时间戳保持不变**（不跟着当前时间走）。恢复供电后自动回到正常态，不需要刷新页面。

---

## 五、踩过的坑

1. **原理图型号是错的**。板上印的是 QMA7981，实际装的是 **QMA6100P**（该型号已 EOL，pin-to-pin 替换）。靠 `CHIP_ID=0x90` 和特有寄存器才确认下来 —— 如果照原理图写驱动，读出来全是 0。
2. **原始数据没标定就不能用**。初版固件直接给原始寄存器值，`ax` 能到 31.77。标定后静置才是 1.00g。
3. **这个传感器没有陀螺仪**。`gx/gy/gz` 三列永远是 0，页面照实显示 0，没有伪造成角速度。

## 六、这一周的一句话结论

**能从板子上采到真数据、自己联网传回来、网页能看到，停采了也不会假装数据是新的。**

缺的一项：VPS 没部署，用的是本机代替（任务卡的备用路径允许，但课程评价证据里写的是「VPS 部署结果」，这一项仍是缺口，已如实标注）。
