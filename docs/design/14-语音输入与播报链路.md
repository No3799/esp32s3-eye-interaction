# 14 · 语音输入与播报链路（第 5 周）

> 任务卡原文：「讲解音频输入、采样格式、语音识别和文本中间结果；先用按键开始/结束录音，完成音频到任务文本。」
> 「复用第4周查询/采集任务处理，再连接语音合成；显示录音、识别、任务执行与播放状态，
> 用同一句任务对照文字和语音入口。」
> 「设备音频未就绪时使用电脑音频，但**明确运行位置**。」

## 0. 一句话

**录一句人话 → 变成文字 → 交给第4周那条已经验证过的自然语言入口 → 把回答念出来。**
语音不是新的一条业务链路，它只是给已有入口换了一个"输入方式"和"输出方式"。

## 1. 运行位置（先说清楚，这是任务卡点名的）

| 环节 | 跑在哪 | 说明 |
|---|---|---|
| 麦克风采集 | **电脑**（浏览器 Web Audio） | 板子没有音频固件，本课不把麦克风硬件开发当前提 |
| 语音识别 | **电脑**（本机离线引擎 vosk + 中文小模型） | 不上传云端，录音不出本机 |
| 任务执行 | 第4周的 `/api/ask` → 服务器 → 板子 | 与文字入口**完全同一条路径** |
| 语音播报 | **电脑**（浏览器 `speechSynthesis`） | 用系统中文语音，不经过服务器 |

页面上常驻一句"录音在电脑、识别在本机、板子不参与音频"，避免把"板子会说话"当成事实。

## 2. 为什么这么选（三个都试过或被排除过）

### 2.1 录音：Web Audio 直接采 PCM，不用 MediaRecorder

`MediaRecorder` 出来的是 **WebM/Opus**，要转成识别引擎要的 16k 单声道 WAV 就得有 ffmpeg。
本机没有 ffmpeg（实测 `ffmpeg/ffprobe/sox` 都没有），而且为了一句语音引入一个转码依赖不划算。

所以走：`getUserMedia` → `AudioContext` → `ScriptProcessor` 取 `Float32` →
按比例降采样到 16k → 手写 44 字节 WAV 头封装。全程在浏览器里，服务端拿到就是标准 WAV。

### 2.2 识别：本地离线 vosk，不用云服务

| 方案 | 结果 |
|---|---|
| 云端语音 API | 需要账号与密钥；课程明确"密钥不得进公共仓库"，本仓库是公开的 |
| Windows 自带识别 | 需要 `Add-Type` / COM，本机安全策略直接拦截（实测两条都被拒） |
| **vosk 离线小模型** | ✅ 选它：纯本地、无需密钥、中文小模型 65MB、加载 0.5 秒 |

模型与运行时放在 `week1/.venv-asr/` + `week1/tools/models/`，**两者都不入库**（`.gitignore` 已排除），
只记录来源与版本，换机器按第 7 节重装。

### 2.3 播报：浏览器 `speechSynthesis`

本机装有中文语音（SAPI: Huihui；OneCore: Huihui/Kangkang/Yaoyao），但 Windows 侧的调用要
`Add-Type` 或 COM，都被拦截。浏览器自带的 `speechSynthesis` 用的是同一批系统语音，
**不需要服务器参与**，也不用装任何东西 —— 于是播报放在前端。

## 3. 关键设计：三件事必须分开说

任务卡要求「无声、识别失败、服务超时都产生可理解反馈」。所以错误码不是笼统一句"识别失败"：

| 错误码 | 什么情况 | 用户该做什么 |
|---|---|---|
| `silence` | 录到了，但峰值 < 200/32768（没声音） | 查麦克风是否静音、离远了一点 |
| `audio_unreadable` | 传上来的不是合法 16k 单声道 WAV | 采集侧出问题了，看浏览器 |
| `empty_text` | 有声音，但没听出词 | 再说一遍，慢一点 |
| `asr_unavailable` | `.venv-asr` 或 worker 不在 | 按第 7 节重装识别环境 |
| `asr_timeout` | 识别超过 30 秒 | 先用文字输入 |
| `too_large` | 录音超过 4MB（约 2 分钟） | 说短一点 |

**为什么这么较真**：如果都回"识别失败"，用户会反复重说同一句话 ——
他根本不知道问题在麦克风、在网速、还是在识别引擎。

## 4. 复用而不是复制

识别成功后的文本，走的是**第4周同一个 `send()`**，也就是同一个 `/api/ask`。

为什么不让语音另开一条执行路径：两条路径一开始一样，改着改着就会长出两种行为
（比如语音允许 100 个采样点、文字只允许 50），那时候"同一句话文字和语音结果不同"
就成了新的 bug。**输入方式可以多，执行路径只能有一条。**

## 5. 四个状态显示在哪

页面「语言」分区顶部有一行状态标签，按顺序变化：

```
麦克风未使用 → 录音中…（说完点「结束录音」） → 识别中…（X 秒 / Y KB）
            → 处理中…（第4周的意图解析） → 播报中… → 就绪
```

对应的中间结果（识别出的文字、识别耗时、意图、工具、状态）都会作为消息元信息留在对话里，
所以"同一句任务用文字问一次、用语音问一次"可以直接对照。

## 6. 已知限制

1. **识别只在电脑上**。板子的麦克风没有固件支持，本课不覆盖；任务卡允许这样，但必须标注运行位置。
2. **半双工**：录音时要等识别完成才能再录，不能边听边说（第6周才处理打断与停止）。
3. **识别精度**：小模型对短指令（"查看上次数据""重新采集一次"）够用，长句会掉字。
   识别结果**不做自动纠错** —— 猜错了比听错了更糟。听错就显示听错的原文，让人看见。
4. **播报不可中断**：目前 `speechSynthesis.cancel()` 只在新一轮播报前调用，用户不能中途喊停（第6周做）。

## 7. 换机器怎么重装识别环境

```bash
cd week1
python -m venv .venv-asr
.venv-asr/Scripts/python.exe -m pip install --no-cache-dir srt cffi requests tqdm websockets -i https://pypi.org/simple
# vosk 的轮子较大，直接从 PyPI 取：
.venv-asr/Scripts/python.exe -m pip install vosk -i https://pypi.org/simple
# 中文小模型（65MB，解压到 tools/models/）：
#   https://alphacephei.com/vosk/models/vosk-model-small-cn-0.22.zip
```

验证：

```bash
.venv-asr/Scripts/python.exe -c "import vosk; print('ok')"
.venv-asr/Scripts/python.exe tools/asr_worker.py <一个 16k 单声道 wav>
```

> 本机实测踩到的坑：**清华镜像上没有 vosk**（报 `No matching distribution`），
> 换官方 `pypi.org` 才有；而且单次大文件下载会被环境中断，最后是分段（2MB）拼出来的。
> 这些不影响业务代码，但换机器的人会再踩一遍，所以记在这里。
