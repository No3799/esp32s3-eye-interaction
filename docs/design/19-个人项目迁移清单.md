# 19 · 个人项目迁移清单

> 用途：把课程要求里"为个人项目做 X"的那些条目，从"待定"落成具体决定。

> 最后更新：2026-11-04

## 1. 个人项目是什么

一句话：**这台 ESP32-S3-EYE 做的「现场求助 + 远端回应」装置。**

- 现场的人：按板子上的键（MENU / PLAY / UP+ / DN−），灯闪一下表示"本地已记下"，不用等网络。
- 网页端的人：看到"谁按的、多久以前、当时环境什么样"，点「我来处理」或「取消求助」。
- 边界：只在本组局域网服务器内流转，**不接任何真实紧急服务**（页面上常驻这句提示）。
  它是个协作提示器，不是报警器 —— 这个定位在第 3 周走查第 10 项里已经明确写过。

第 4 周的验收记录里写过一句「本项目即个人项目」，这份文档就是把那句话展开成可执行的清单。

## 2. 期末迁移的交互模块（第 9 周的决定）

**选定：「求助事件 + 三级反馈」这一整块。**

不是选"语音"，也不是选"视觉推理"，理由三条：

| 理由 | 说明 |
|---|---|
| 它是唯一有"人真的需要帮忙"语义的闭环 | 其他模块（语音、视觉、多源状态）都是它的支撑：语音是另一种触发，视觉是"当时画面"，多源状态是"当时数据新不新" |
| 三级反馈的分法可以直接搬 | ① 本地确认（设备上）② VPS 接收（服务器上）③ 查看者回应（人）—— 少一级就会出现"以为对方收到了" |
| 它的失败模式已经被踩过并修好 | 事件 id 跨重启唯一、重复上报幂等、断网时本地仍确认、无远端证据不显示"已收到" |

**带走的**：事件表结构（`id / created_ms / state / snapshot`）、三级反馈的字段拆分、
确认与取消的状态机、幂等写入、卡片上的"当时数据新不新"。

**不带的**：这台板子的 QMA6100P 驱动、OV2640 取图、Wi-Fi 上报节奏 —— 那些是硬件相关的，
换设备就要换。

## 4. 三项的具体实现

### 4.1 模型判断的纠错入口（第 8 周）

- 纠错的对象：**画面可用性**，不是"这是什么物体"。因为它决定用户下一步动作
  （能用就继续，不能用就重拍），而场景分类不改变任何动作。
- 位置：求助事件卡片上，模型判断那一行后面直接跟「判错了？」三个按钮。
  **看到判断的地方就是能改判断的地方** —— 不用切到「影像」分区再找一遍。
- 落库：走第 8 周已有的 `POST /api/vision/<id>/feedback`，`wrong` 必须带
  `corrected_label`，原判保留在 `vision_store`，卡片上显示 ~~看不清是什么~~ → 已纠正为 能看清。
- 代码：`web/index.html` 的 `renderHelp()` / `correctHelpVision()`；
  接口侧在 `server.py::_help_vision()`。

### 4.2 数据过期与来源缺失（第 10 周）

- 计算口径：取求助事件 `created_ms` **之前**最近一条 `readings`，
  算它与事件时刻的差；≤5 秒算"新"，>5 秒算"过期"，一条都没有算"无来源"。
- 为什么用"事件时刻"而不是"现在"：这条求助是十分钟前发生的，用现在的数据去解释它，
  等于用后来的信息改历史。
- 文案上必须把两件事分开：**事件有效**（人按的键）／**数据可能过期**（不能用来推断现场）。
- 代码：`server.py::_help_freshness()`；网页 `renderHelp()` 的 `freshLine`。

### 4.3 迁移模块（第 9 周）

见第 2 节。真正的交付物是这份清单本身：**哪个模块、带走什么、留下什么、为什么**。
没有这份清单，"迁移"就只是一句口头承诺。

## 5. 怎么复现

```bash
# 1) 起服务器（设备在线时会持续上报）
python week1/server/server.py --port 8000 --host 0.0.0.0

# 2) 三项一起验（接口 + 真浏览器点击）
python week1/tools/test_migration_personal.py
```

测试里"过期 / 无来源"两种用的是**测试夹具**（直接写两条事件到 help_events 造时间间隙，
跑完删除）—— 因为真机上板子 1 Hz 一直报，按键那一刻数据总是新的，这两种情况复现不出来。
夹具 id 带 `TEST`，不与真实事件混淆。

## 6. 不迁的东西

- **不做定位**：本机没有 GNSS，任何坐标都不可能是这台设备的位置（第 4、10、11 周都写过）。
- **不做"危险"推断**：危险只能由人按求助键或自述触发，画面遮挡、模型标签都推不出来。
- **不做定时抓拍**：只在用户请求或求助事件时取图，避免"看起来一直在监控"。
- **不接真实紧急服务**：页面上常驻声明，避免被当成报警装置。
