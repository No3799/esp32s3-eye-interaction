## 2. 本工程的首版字段（按代码实测，不是设计稿）

### 2.1 上行事件 A：`readings`（传感器观测，23 列）

| 字段 | 类型 | 单位 / 取值 | 语义 |
|---|---|---|---|
| `id` | INTEGER | 自增 | 服务器侧序号 |
| `device_id` | TEXT | — | 设备标识 |
| `seq` | INTEGER | 递增 | 设备自增序号（用于识别丢包/重启） |
| `ax` `ay` `az` | REAL | **g** | 三轴加速度 |
| `gx` `gy` `gz` | REAL | — | **恒为 0**（本板无陀螺仪，QMA6100P 只有加速度） |
| `device_ms` | INTEGER | ms | 设备侧时刻（`esp_timer`，开机计时） |
| `server_ms` | INTEGER | ms | 服务器接收时刻（墙钟） |
| `src_ip` | TEXT | — | 来源 IP |
| `temp_c` | REAL | °C | 芯片温度 |
| `free_heap` / `min_free_heap` / `total_heap` | INTEGER | byte | 内存 |
| `rssi` | INTEGER | dBm | WiFi 信号 |
| `request_id` | TEXT | `CMD-…` / `BTN-…` / NULL | **关联请求**；定时上报为 NULL |
| `trigger` | TEXT | `timer` \| `command` \| `button` | **来源模式** |
| `cmd_state` | TEXT | `received` \| `done` \| `failed` \| `timeout` \| NULL | 指令执行状态 |
| `cmd_note` | TEXT | — | 失败原因 / 部分送达说明 |
| `button` | TEXT | `MENU` \| `PLAY` \| `UP+` \| `DN-` \| NULL | 按键名 |
| `press_delay_ms` | INTEGER | ms | 按下 → 首条采样组装完成 |

### 2.2 上行事件 B：`help_events`（求助事件，15 列）

| 字段 | 类型 | 取值 | 语义 |
|---|---|---|---|
| `id` | TEXT | `BTN-<6位hex>-MENU-0001` | **设备生成的事件 id**，带随机前缀防跨重启撞车 |
| `device_id` | TEXT | — | 设备标识 |
| `button` | TEXT | 四个键名 | 触发键 |
| `source` | TEXT | `button` \| `web` | **来源** |
| `simulated` | INTEGER | 0/1 | 模拟/演练数据必须标出 |
| `local_feedback` | TEXT | `led` / NULL | 设备自报的本地反馈方式 |
| `snapshot` | TEXT | JSON | 当时环境快照 |
| `press_delay_ms` | INTEGER | ms | 按下 → 首条采样 |
| `created_ms` | INTEGER | ms | 服务器落库时刻（= ② VPS 接收证据） |
| `state` | TEXT | `open` \| `acked` \| `cancelled` | 事件状态 |
| `ack_ms` / `ack_by` | INTEGER / TEXT | — | ③ 查看者回应时刻与回应人（**唯一来源**） |
| `cancel_ms` / `cancel_reason` | INTEGER / TEXT | — | 取消 |
| `reply_cmd_id` | TEXT | `CMD-…` | 回应/取消下发的指令 id |

### 2.3 下行命令：`commands`（18 列）

| 字段 | 类型 | 语义 |
|---|---|---|
| `id` | TEXT | 指令 id（`CMD-YYYYMMDD-NNNN`） |
| `device_id` / `type` | TEXT | 目标设备 / 类型 |
| `params` | TEXT(JSON) | `{"samples":n,"interval_ms":m}` 或 `{"event_id":…,"action":"ack\|cancel"}` |
| `status` | TEXT | `issued` → `delivered` → `received` → `done` / `failed` / `timeout`（**只进不退**） |
| `created_ms` / `delivered_ms` / `received_ms` / `done_ms` | INTEGER | 四阶段时间点 |
| `timeout_ms` / `timeout_stage` | INTEGER / TEXT | 超时时刻 / `accept`（没来取）或 `exec`（取了没做完） |
| `accept_deadline_ms` / `exec_deadline_ms` / `exec_timeout_ms` | INTEGER | 两段超时预算 |
| `sample_count` / `first_reading_id` / `last_reading_id` | INTEGER | **命令 → 新观测**的物证 |
| `note` | TEXT | 结果说明 |

**命令类型白名单（服务端强制）**：`recollect` / `pause` / `resume` / `help_reply`

### 2.4 接口清单（HTTP）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/data` | 上行观测（响应体里捎带下行指令） |
| POST | `/api/poll` | 暂停期间的心跳（不写 readings，只为取指令） |
| POST | `/api/help` | 上行求助事件 |

| GET | `/api/devices` · `/api/camera` · `/api/camera/status` | 设备 / 摄像头 |

## 3. 对照 A：工作流课的五项约定

> 原文（单元二）：「为系统确立 `InputAdapter` 接口规范，约定**字段、单位、采样时间戳、来源模式和失败/降级状态**。」
> 原文（第2周跨课衔接）：「形成**事件时间、类别、状态、来源**的最小约定草稿。」

| 约定 | 本工程对应 | 判定 |
|---|---|---|
| 字段 | 三张表共 56 列，均有建表语句 | ✅ |
| 单位 | `ax…az` 单位 g；`device_ms/server_ms` 毫秒；`temp_c` 摄氏；`rssi` dBm | ⚠️ **靠命名约定，没有机器可读的单位字段** |
| 采样时间戳 | `device_ms`（设备）+ `server_ms`（服务器）**双时间戳** | ✅ |
| 来源模式 | `readings.trigger` ∈ timer/command/button；`help_events.source` ∈ button/web | ✅ |
| 失败/降级状态 | `commands.status` + `timeout_stage`；`readings.cmd_state` + `cmd_note`；`help_events.state` | ✅ |

**结论 A：五项都有对应物，可直接对接。唯一偏软的是「单位」—— 靠字段名和文档表达，跨课对接时容易问"这是 g 还是 m/s²"。**

## 4. 对照 B：视觉课「最小交接」的输出字段

> 原文（课程标准七）：「**输出关联输入记录与 request_id，分开采集时刻、推理时刻、模型版本、运行状态、结果和分数类型**；检测另列框格式与坐标空间。」

| 视觉课要求 | 本工程现状 | 判定 |
|---|---|---|
| 关联输入记录与 `request_id` | `readings.request_id`（定时为 NULL）+ `commands.first/last_reading_id` | ✅ |
| 采集时刻 | `device_ms` + `server_ms` | ✅ |
| **推理时刻** | — | ❌ 无 |
| **模型版本** | — | ❌ 无 |
| **运行状态 / 运行位置**（电脑 / 边缘 / 服务器 / 真机） | — | ❌ 无（实际全在电脑上，只在文档里声明） |
| 结果 | `ax/ay/az` 是**传感器读数**，不是模型结果 | ⚠️ 有读数、无模型输出 |
| **分数类型**（置信度 / 阈值 / 拒识） | — | ❌ 无 |

**结论 B：模型侧 4 个字段全缺。** 这在本周是正常的 —— 交互课第 3 周还没有模型，视觉课第 2—3 周才刚建 1D CNN。但它不是"以后再说"的问题：**接口现在不预留，第 4 周接模型就要改表、改协议、重跑全部回归。**

## 5. 对照 C：视觉课第 3 周「来源差异」

> 原文（第3周两课接点）：「保持原实体操作任务，**显示"用户操作"和"模型判断"来源差异**；补一个判断错误/不确定的反馈样例。」

| 要求 | 本工程 | 判定 |
|---|---|---|
| 区分「用户按下按钮」 | `trigger='button'` + `button='MENU'` + `request_id='BTN-…'` | ✅ |
| 区分「模型判断发生运动」 | `trigger` 枚举里**没有 `model`** | ❌ |

## 6. 差异清单与处置建议

| # | 差异 | 影响 | 建议改法 | 时机 |
|---|---|---|---|---|
| D1 | 无推理时刻 | 分不开「采集时刻 / 推理时刻」，V01 要求"来源、输入、模型和时间可对应" | `readings.infer_ms INTEGER NULL` | 接模型前 |
| D2 | 无模型版本 | V08「同输入、预处理、标签和版本核对」做不到 | `readings.model_version TEXT NULL` | 接模型前 |
| D3 | 无运行位置 | V09「区分电脑、边缘、服务器与真实目标设备，导出不冒充上板」做不到 | `readings.run_place TEXT NULL`，取值 `pc` / `edge` / `server` / `device` | 接模型前 |
| D4 | 无分数类型 | 置信度/阈值/拒识混在一起 | `readings.score REAL NULL` + `score_type TEXT NULL` | 接模型前 |
| D5 | `trigger` 没有 `model` | 无法表达"模型触发" | 枚举扩为 `timer` / `command` / `button` / `model` | **现在**（成本≈0） |
| D6 | 单位不可机器读 | 跨课对接要口头解释 | 在接口文档写明单位（本文 2.1 已写明）；暂不加字段 | 文档级 |
| D7 | 无固件版本 | 版本核对缺一环 | `readings.fw_version TEXT NULL` | 接模型前 |

**共同点：D1–D4、D7 只是加可空列，不改变任何现有行为**（全部写 NULL），却能保证第 4 周接模型时不改协议。这是成本最低的前向兼容。

⚠️ 但**加列不是零成本**：要同步改 3 处（建表语句、`row_to_dict`、固件 payload）+ 重跑回归。所以要不要现在做，是需要决定的取舍，不是"顺手"。
