# 第 7 周 · 按需取一张环境图像

> 这是**第 7 周结束时**的仓库快照。整门课的完整说明看
> [`main` 分支](https://github.com/No3799/esp32s3-eye-interaction/tree/main)。

用户说"让我看看那边现在什么情况"，系统就得去拍一张。难的不是拿到图，而是**说清楚**：

- 这张是哪一刻的？
- 是这次拍的，还是上一张留下来的？
- 拍到了，但画面能不能用（遮住了？一片黑？）

最危险的动作是**拿上一张图顶着说"拍到了"** —— 用户会以为那就是现在。

## 一、这一周做了什么

| 做了什么 | 落在哪 |
|---|---|
| `POST /api/snapshot` 按需采集，**只在请求或教学事件触发后取图**，不做连续拍 | `server/server.py` |
| 四种状态必须能用**文字**区分：采集中 / 采集成功 / 画面不可用（遮挡或纯色）/ 采集失败 | `web/index.html` |
| "是不是本次"的判据要**两条同时成立**：回执 `done` **且** 库里有带同一 `request_id` 的新记录 | `server/snapshots.py` |
| 回放与实拍分离：导入的历史图 `source=replay`，**不计入"上次成功"** | 同上 |
| 画面判定顺序固定：先认 JPEG → 解码 → 尺寸 → 亮度/方差 | 同上 |
| 失败不拿旧图顶：有上次成功就明写「上次成功（时间），**不是本次**」；没有就清空写「本次没有拿到画面」 | `web/index.html` |
| 快照存 JPEG + `index.jsonl` 索引，可按时间回取 | `data/snapshots/` |
| 中继层 `ProxyHandler({})`：局域网地址一律绕过系统代理 | `server/camera_relay.py` |

**判定顺序为什么不能反**：一张全黑的图只有约 1.5KB，先看文件大小会判成"太小"，
用户就被指到错误的方向去查。先认出它是合法 JPEG，再看亮度，才知道是"被遮住"。

## 二、实测数据

| 项目 | 结果 |
|---|---|
| 真机按需采集 | **320x240 / 1623 ms**（本周末实测，`is_this_attempt=true`，JPEG 可回取） |
| 纯黑 JPEG（1.5KB） | 判 `too_dark`（被遮挡），不是 `too_small` |
| 纯灰 JPEG（1.8KB） | 判 `flat_frame`（纯色），不是 `too_small` |
| 注入失败后 | `is_this_attempt=false`，回复写明"那不是本次采集的结果" |
| 回放导入 | 标 `source=replay`，不计入"上次成功"，越界目录返回 403 |

**统计：22 项中 ✅ 19 项、⚠️ 1 项、❌ 2 项。**

两项 ❌ 要外部条件：教师准备的教学场景与图像样例、模型课提供的轻量视觉基线
（本项目用自己的桌面场景与自建判定顶替，如实记为未做）。
⚠️ 一项：端侧课没提供按需图像接口，用板子已有的 `/capture` 自建 —— 属**替代而非对齐**。

> 2026-11-02 补记：画质从 QVGA(320x240) 升到 VGA(640x480)、打开 vflip 纠正上下颠倒，

## 三、怎么跑起来

```bash
# 起服务带故障注入，才能确定地造一次采集失败
python week1\server\server.py --port 8000 --host 0.0.0.0 --fault-injection
```

- 网页：<http://127.0.0.1:8000/#camera>，点「拍一张」
- 接口与记录自测：`python week1/tools/test_week7_snapshot.py`
- 画面判定（离线，不需要板子）：`python week1/tools/test_week7_judge.py`
- 界面四态逻辑（离线）：`python week1/tools/test_week7_ui_logic.py`

## 五、分支与周次对照

仓库按周打了快照分支。**远端默认分支是 `main`，含全部已完成周次**；
想看某一周结束时的状态，切到对应分支即可。

| 分支 | 对应阶段 | 说明 |
|---|---|---|
| **`main`**（远端默认分支） | 最新主线 | 含第 1—7 周全部内容 |
| `week7` | 第 7 周 | 按需获取一张环境图像（采集四态 + "是不是本次拍的"判定，本文档所在分支） |
| `week6` | 第 6 周 | 语音任务的澄清与停止（有限多轮上下文、取消、迟到结果隔离） |
| `week5` | 第 5 周 | 按键说话 + 板载麦克风录音 + 离线识别 + 语音播报 |
| `week4` | 第 4 周 | 自然语言查询与请求采集（两个受限工具） |
| `week3` | 第 3 周 | 实体按键发起教学求助 + 反馈闭环 + 回应与取消 |
| `week2` | 第 2 周 | 双向指令通道 + 回执状态机 |
| `week1` | 第 1 周 | 单源采集 + 上行链路 + Web 实时展示 |

每个 `weekN` 分支是**累积快照**：含第 1 周到第 N 周的全部文件，不是只放那一周的增量。
