# 第 2 周 · 让网页能反过来指挥设备

> 这是**第 2 周结束时**的仓库快照。整门课的完整说明看
> [`main` 分支](https://github.com/No3799/esp32s3-eye-interaction/tree/main)。

原来这条链路是单向的：板子推数据、网页看数据，刷新再多次也只能看到已有记录，
没有任何办法让设备**再采一次**。

这一周补上反方向的通道，并把它拆成四段可核查的证据：
服务器受理 / 指令下发 / 设备接收 / 执行完成。

## 一、这一周做了什么

| 做了什么 | 落在哪 |
|---|---|
| 下行指令通道：网页 POST `/api/command` → 生成 `request_id` → 指令**搭在板子下次上报的响应体里**下发 | `server/commands.py`、`/api/data` |
| 状态机 `issued → delivered → received → done`，**只进不退**，终态冻结 | `commands.py` |
| 超时由后台线程主动落库，且**分两段记**：`accept`（设备没来取）/ `exec`（取了没做完） | `commands.py` 的 sweep |
| 新采的数据带**同一个** `request_id` 入库，能精确关联到触发它的那次请求 | `readings` 表加 5 列（幂等迁移） |
| 重复点击闸门放在**服务器**（界面 disabled 拦不住两个标签页），按"同类"不按设备全局 | `/api/command` |
| 同 `request_id` + 同终态重复提交 → `{duplicate:true}`，不再入库 | 同上 |
| 网页「主动交互」面板 + 四阶段时间线；表格「触发」列三种标记 | `web/index.html` |
| 固件：读回响应体、`cJSON` 解析、`build_payload()` 抽出来供多种触发复用、`run_command()` 执行指令采集 | `firmware/esp32_imu/main/main.c` |
| 首版状态图 | [`docs/design/10`](docs/design/10-指令状态机与状态图.md) |

## 二、实测数据

| 项目 | 结果 |
|---|---|
| 一次完整指令（采 12 条、间隔 100ms） | 四段齐全，13 条新记录全部带同一 `request_id` |
| 端到端耗时 | 4~13 秒 |
| 板子一次 `POST /api/data` | **0.5~2.5 秒** —— 不是代码慢，是网络往返慢 |
| 失败态 | 真机注入故障验证，含对照组 |
| 超时 | 分 `accept` / `exec` 两段记录，两者性质完全不同 |

## 三、怎么跑起来

```bash
cd week1/server
python server.py --port 8000 --host 0.0.0.0
```

- 网页：<http://127.0.0.1:8000/>
- 板子（`team01-esp32s3eye`）连上 WiFi 后自动以 1Hz 上报
- 没有硬件时用模拟器：`python week1/sim/esp32_sim.py`

## 五、分支与周次对照

仓库按周打了快照分支。**远端默认分支是 `main`，含全部已完成周次**；
想看某一周结束时的状态，切到对应分支即可。

| 分支 | 对应阶段 | 说明 |
|---|---|---|
| **`main`**（远端默认分支） | 最新主线 | 含第 1—7 周全部内容 |
| `week7` | 第 7 周 | 按需获取一张环境图像（采集四态 + "是不是本次拍的"判定） |
| `week6` | 第 6 周 | 语音任务的澄清与停止（有限多轮上下文、取消、迟到结果隔离） |
| `week5` | 第 5 周 | 按键说话 + 板载麦克风录音 + 离线识别 + 语音播报 |
| `week4` | 第 4 周 | 自然语言查询与请求采集（两个受限工具） |
| `week3` | 第 3 周 | 实体按键发起教学求助 + 本地/远端反馈闭环 + 回应与取消 |
| `week2` | 第 2 周 | 双向指令通道 + 回执状态机（本文档所在分支） |
| `week1` | 第 1 周 | 单源采集 + 上行链路 + Web 实时展示 |

每个 `weekN` 分支是**累积快照**：含第 1 周到第 N 周的全部文件，不是只放那一周的增量。
